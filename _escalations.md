# Escalations and org-level patterns

Placeholder. The real file is `apprentices/escalations.md`, which is private and not tracked here.
If it doesn't exist yet, create it from this shape.

Things that surface through apprentice check-ins and evals but aren't apprentice problems.

**This file is the record.** Escalation items don't live as repeated bullets in the
`apprentices/*-checkins.md` files. Everything about an item (instance list, dates, status, which
prep or check-in it was carried in) lives in one place.

**What belongs here:** anything whose fix has an owner outside this desk. Curriculum gaps,
eval-form wording, program-side process, cohort-level patterns.

**What doesn't, 1: my own homework.** Cross-apprentice items I can actually fix (team norms,
process I set) live in `apprentices/team-norms.md`. The line is who owns the fix, not how many
people it touches.

**What doesn't, 2: per-person evidence.** That stays in `apprentices/<name>.md`. An escalation
cites apprentices as instances, it isn't a record of their performance.

**Never inflate the instance count.** Only apprentices where it was confirmed are instances.
Someone the question was never put to is `Unconfirmed`.

**`Ask` lines are name-free on purpose.** They lift straight out when something goes upward.
